# ZIP 与 CBZ 图片浏览器实施规划

日期：2026-10-12。项目暂用名：ZipGallery，可随后更名。

## OpenComic 试用后的实施调整

用户试用 OpenComic 后确认恢复开发：它能满足漫画阅读，但用户仍需要在压缩包内直接、方便地浏览图片。首屏应为可导航的压缩包内容视图，以图片缩略图网格为核心；进入子目录、返回上级和面包屑导航提升到第一阶段，不能仅交付漫画阅读页或 Quick Look 弹窗。点击图片进入大图，返回后保留所在目录、选中项和滚动位置。

继续沿用 ZIP/CBZ 和 MyGo 的既定范围，不据此扩展为全格式压缩软件。复用已保存的工程改动继续实现；此次用户已明确撤销暂停并要求开工。

## 目标与已确认决策

用 egoist/MyGo 创建桌面图片浏览器。用户打开 ZIP 或 CBZ 后，直接看到缩略图网格，点击图片即可放大并连续翻页，无需手动解压整个压缩包。首先在 macOS 上运行，业务逻辑保留跨平台能力。

首版专攻 ZIP 和 CBZ。两种扩展名共用 ZIP 读取器，按实际内容验证格式。暂不接入 RAR、7z 或通用压缩管理功能。参考 MacPacker 的分层方式，无需复制其 Swift 代码或捆绑 7-Zip。

“免解压”指用户无需手动解压或等待完整解包；内部允许按需解压单张图片和使用有上限的应用缓存。不能先完整展开压缩包再呈现界面。

## 第一阶段必须交付

1. 可启动的 MyGo macOS 应用，提供选择 ZIP/CBZ 的入口。
2. 正确枚举包内图片，支持子目录，过滤目录项、__MACOSX 和资源叉文件。
3. 缩略图网格渐进加载，优先当前可见区域，显示文件名和加载失败状态。
4. 点击缩略图进入大图；上一张、下一张、方向键翻页、适应窗口、基础缩放；退出大图保留网格位置。
5. 文件名自然排序，例如 1.jpg、2.jpg、10.jpg；排序稳定，以完整路径或条目序号处理同名文件。
6. 图片先支持 JPEG、PNG，WebP 在所选解码链路确认可用后加入。动画、RAW、HEIC、超大图分块显示不阻塞首版。
7. 错误可理解：格式不支持、无图片、文件损坏、图片解码失败、文件不可达；单张失败不阻断其他图片。
8. 使用生成的非敏感测试图片和压缩包，验证端到端缩略图及翻页。保留可复现的启动方法。

第一阶段完成后继续第二阶段。若框架或环境存在真实阻塞，说明具体原因、已尝试方案及可运行部分；不要只交项目模板或静态假界面。

## 第二阶段 日常使用

- 本地文件、拖入文件、系统打开文件事件、最近打开统一调用一个 OpenLocation 入口。
- 保存最近打开记录和阅读进度，恢复时使用条目身份而非仅保存排序位置。
- 文件夹导航及“全部图片”视图。
- 支持系统已挂载的 SMB 共享，通过可随机读取的文件接口访问；打开时不复制整个压缩包到本地。
- 缩略图磁盘缓存、内存缓存上限、清理入口、文件变化后的失效处理。
- 声明支持 ZIP/CBZ 文件打开；默认关联是用户选项，不自动改动现有系统默认程序。CBZ 为主要推荐关联，ZIP 保留可选。
- 新进程收到文件后启动/唤醒主窗口并交给统一打开入口；处理冷启动与已运行状态，避免重复窗口或重复打开。

## 分层与接口原则

### 桌面与界面

采用 MyGo + Go 后端 + WebView 前端，优先 React + TypeScript。初始化前核对 MyGo 当前文档、实际 Go/Bun 版本并锁定依赖。TanStack Virtual 可用于虚拟网格，PhotoSwipe 可用于大图浏览；通过小验证决定是否引入，避免为了集成组件引入多余复杂度。

MyGo 负责窗口、文件对话框、生命周期和文件打开事件；不让 ZIP 解析逻辑依赖窗口或前端。

### 位置层

使用可扩展的 Location 描述来源，至少区分 local 与 smb。SMB 身份由服务器、共享名、共享内相对路径组成，当前挂载路径只是访问映射，不能把 /Volumes 下的绝对路径当作永久身份。

第一版没有可靠的挂载身份解析时，明确记录为 mounted/local 来源并允许重新定位，不能猜测 SMB 地址或声称具备自动重连。直连 SMB 的凭据未来交给系统凭据存储，位置记录不保存明文密码。

位置层向读取器提供大小、io.ReaderAt 或等价随机读取能力、版本信息和关闭操作。应用内选择、拖入、系统文件关联和最近打开都先生成 Location，再交给统一入口。打开会话拥有文件句柄生命周期。

### 压缩包层

首选 Go 标准库 archive/zip，支持常用 Store/Deflate 与 ZIP64。首版不承诺加密 ZIP、分卷或所有 ZIP 压缩方法；遇到不支持情况明确报错。

读取目录建立条目索引，然后仅打开需要的图片条目。条目 ID 使用会话 ID 加条目序号等稳定标识，不能只靠文件名。列目录不解码全部图片，也不读取整包到内存。

### 图片与调度层

任务优先级：当前大图、可见缩略图、邻近预读、其余后台任务。限制并发，合并同一条目的重复请求，切包和滚动后取消或丢弃过时任务，避免旧请求覆盖新会话。

缩略图由后端生成真实的小图，不把全部原图传到前端再用 CSS 缩小。使用已有解码/缩放组件；处理 EXIF 方向，限制输入解压字节数、图片像素数和解码并发。PNG/JPEG 之外按验证情况增加。

通过 MyGo 自定义协议或经验证的二进制通道传图。RPC 主要传命令、索引和状态，不用 Base64 批量传大图。协议仅接受已打开会话中的条目 ID，不暴露任意本地文件读取。

缓存键包含压缩包身份、版本和条目身份/缩略图参数；本地可使用大小及修改时间作为初步版本线索，但保留显式刷新。限制磁盘及解码后内存占用，按最近使用淘汰，关闭会话释放句柄和临时资源。

## 后续 SMB 直连

在读取和位置接口稳定后，加入应用内服务器/共享浏览、登录与重连。对实际 SMB 客户端验证随机读取、取消、超时与断线行为。ZIP 首先读取末尾目录，再读取目标条目的数据段；通过有限预读减少网络往返。

离线时保留最近打开和进度，提示重连或重新定位，不自动删除记录。跨平台钥匙串、NAS 兼容性和网络延迟需要独立验证。

## 实施顺序

1. 检查开发环境和目录指令；初始化 MyGo 项目、确认最小窗口能运行。
2. 建立 ZIP 会话、图片条目索引和读取接口，用生成的 ZIP/CBZ 测试。
3. 打通真实缩略图和大图传输，加入虚拟网格及翻页。
4. 补自然排序、子目录、错误处理、取消任务和资源限制。
5. 构建并启动应用，使用 UI 实际验证打开包、看缩略图、翻页和返回。
6. 在第一阶段可用的基础上补最近记录、进度、挂载 SMB 及文件打开事件。

## 验收与性能记录

- 小 ZIP 与相同内容的 CBZ 都能显示真实缩略图并连续翻页。
- 包含 1、2、10 命名、中文日文、子目录、重复 basename 的样本排序和寻址正确。
- 空包、非图片包、损坏图片及不支持压缩方法有明确提示。
- 快速滚动、快速翻页及连续切包不会串图；关闭会话释放资源。
- 对上千图片、几 GB 的代表性包，记录冷/热首屏耗时、翻页延迟、峰值内存和缓存占用；报告测试硬件、图片规格、压缩方法和本地/SMB 来源。数据必须实测，不预先声称“秒开”。
- 缩略图首次生成需要读取并解码图片，读取成本随可见图片增长；不得以预先整包解压掩盖首屏等待。
- SMB 没有现成挂载环境时报告未验证，不能把本地测试当作 SMB 验证。
